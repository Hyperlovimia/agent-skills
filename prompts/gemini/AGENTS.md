# 全局 AGENTS.md

## 多会话与 Git worktree

- 遵循仓库 `协作流程` 的分支与提交规范；并行会话各自使用独立 worktree 和任务分支，已有隔离环境可沿用。
- AI 根据任务与仓库状态，自主选择目录、初始化环境，并管理 worktree 的创建、复用与清理。
- 保持各会话的代码、运行环境与产物隔离，只处理本任务的改动，保护其他会话及用户未提交内容；清理前确认成果与需保留的产物已保存。
- 并行 worktree 不自动共享虚拟环境。若当前 worktree 没有 `.venv` 等虚拟环境，优先使用主分支的环境。

## T3 Code 子代理委派

> 本功能依赖 T3 Code 环境。

目标是在有限的 Gemini 额度下，将 Gemini 聚焦于核心判断、疑难研判、架构取舍与统筹，把繁杂的搜寻、检索与常规执行外包给 Codex（GPT）子代理，减少重复工作与主线程上下文开销。

- **主动外包（优先 Codex/GPT）：** 代码库搜寻、多文件检索、日志/文档阅读与信息提取、事实核对、对比整理、常规实现与测试等**不涉及核心决策与取舍**的繁杂工作，主动通过 `delegate_task` 委派给 Codex（GPT）子代理，无需等待用户要求。
- **主线程留白与额度保护：** 仅将核心判断、疑难研判、架构取舍、主导对抗审查、用户沟通及 1–2 次定向读取即可完成的小操作留在 Gemini 主线程；**避免调用 Antigravity 内置子代理（`invoke_subagent`）**，除非用户明确要求或依赖 Antigravity 专属能力。

### 协作与边界

- **只交事实与执行，不代主代理定调：** 日常 GPT 子代理只输出客观事实、代码/日志证据路径、约束清单与验证结果，**不要把疑难根因研判、架构设计或跨模块取舍外包给日常子代理**，避免主线程被保守结论先入为主。
- **一次派清、静默交付：** 派发时一次性写清目标、背景约束、输入材料/路径、工作目录、范围边界、验收检查与交付格式，要求子代理默认静默执行至可验收交付（仅实际阻塞、改变范围的新发现或下游等待的阶段交付才发中间消息）。
- **不重复执行：** 派发后不在等待期间重读同一批文件、重跑同一组命令或重算同一批状态；收到交付后直接基于其证据与验证结果独立研判或集成。
- **充分利用子代理上下文：** 同一调研、检索或实现子任务的追问、补充查证或续做，优先通过 `t3_thread_send` 发往原 `childThreadId` 复用上下文；常规独立审查或二次复核新开 `delegate_task`（多轮对抗式审查除外）。

### 模型和推理强度

委派给 Codex（`providerInstanceId: "codex"`）时，显式指定 `model` 与 `options.reasoningEffort`：

- *默认（调研检索、资料整理、常规实现与验证）——GPT-6.2 Sol High：* `gpt-6.2-sol`，`reasoningEffort: "high"`。
- *重复查询、简单操作与计算机操作——GPT-6.1 Terra Max：* 批次查询、按清单核对文件、提取日志字段、固定规则批量汇总及独立计算机操作，使用 `gpt-6.1-terra`，`reasoningEffort: "max"`。
- *疑难研判与方案对抗审查：* 疑难根因研判、架构设计与跨模块取舍留在 Gemini 主线程自主完成；仅当主方案成形后确需独立批判性挑刺或高风险核对时，再走多轮对抗式审查流程委派高强度审查模型，不在日常单轮委派中做无护栏的方案审查。
- 用户明确指定 Provider、模型或推理强度时，优先遵循用户要求。
