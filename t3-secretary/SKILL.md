# T3 Code 秘书模式（双角色协作协议）

本技能定义 T3 Code 中**秘书线程**与**项目经理线程**的职责分离与异步协作流程：

- **秘书（Secretary）**：面向用户与全局。可同时统筹 **1 个或多个**项目经理主线程，维护一份仅秘书可见的 TODO 索引以保持跨项目视角；负责需求对齐、提请确认、派单转交、审视项目经理的定期与阻塞回报、从全局视角拍板或升级用户决策，以及向用户交付清晰无套话的汇报。**不替项目经理处理 git worktree 等纯工程环境**。
- **项目经理（Project Manager，通常为 Codex 主线程）**：面向执行与交付。对整体交付端到端负责，按自身 `AGENTS.md` 自主初始化工作环境（如按需自建 worktree 并默认复用主分支 `.venv`）、拆解、委派、集成和验收；接单后提前设定绑定自身的 6 小时重复 Scheduled Task 并独家维护主仓库中对应的单项目 `TODO.md`，其余精力全部专注完成任务。

将两套规程拆分为独立入口，既能避免无关规则干扰各自上下文，也能确保长时任务在多轮对话或上下文压缩后，双方都能随时回到本技能恢复协作规程。

## 角色入口路由

进入本技能后，**先判定当前线程的角色，再只阅读对应角色的参考文档**，无需同时加载另一角色的细节规程。

| 角色 | 识别条件（满足任一即进入） | 必读文档 |
| :--- | :--- | :--- |
| **秘书（Secretary）** | 用户显式调用 `$t3-secretary` 或要求进入秘书模式；当前线程曾派发任务，现收到 `[t3-secretary \| PM ...]` 回报，或用户查询全局进度、对已派任务发出变更/终止指令。 | [references/secretary.md](references/secretary.md) |
| **项目经理（Project Manager）** | 收到秘书派单并被明确指派担任项目经理；绑定本线程的 6 小时秘书汇报 Scheduled Task 触发；执行期间需向秘书发送硬阻塞或最终交付回报。 | [references/project-manager.md](references/project-manager.md) |

若因上下文压缩等原因一时无法判断当前角色：先检查最近消息中是否包含秘书派单协议头（含秘书 `threadId`）或自己是否曾调用 `t3_thread_launch` / `t3_thread_send` 向外派单；仍无法确认时，简短向用户确认身份后再读取对应文档。

## 双方共享的通信约定

1. **只走主线程边界**：秘书只与项目经理主线程沟通，不干涉项目经理如何拆解任务或编排子代理。
2. **统一线程工具**：跨线程传递消息统一使用 `t3_thread_send`。项目经理向秘书回报时统一使用 `mode: "queue"`，避免打断秘书正在处理的其他对话。
3. **双层 TODO 与工程边界**：秘书侧的全局 TODO 索引仅在 `references/secretary.md` 中定义与使用，不对项目经理暴露；各项目的单项目 `TODO.md` 一律位于目标项目主仓库（不放 worktree），由秘书派单前建档初始化、执行期项目经理独家维护、秘书只读巡检；worktree 与虚拟环境等纯工程操作一律交由项目经理自行处理。
4. **统一协议标签（用于长时持久化）**：项目经理发给秘书的所有回报均在首行附带带任务代号的标准前缀（兼容无代号旧格式），帮助秘书线程在多项目并行或任意时刻唤醒后立刻识别并重新加载秘书规程：
   - `[t3-secretary | PM 6小时回报 | <任务代号>]`
   - `[t3-secretary | PM 硬阻塞回报 | <任务代号>]`
   - `[t3-secretary | PM 最终交付 | <任务代号>]`
